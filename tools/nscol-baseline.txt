# The `type` class carries four defects pinned red on purpose. Each has a
# fixture that states the behaviour demanded rather than the behaviour
# observed, so the fixture goes green when the defect is fixed and not
# before. None is fixed in the lane that added them.
#
#   type_param_vs_contested_import{,_return}   (neg, neg-native)
#     A type parameter loses to a contested imported name: `fn ident[T]`
#     with two modules exporting `T` is reported as an ambiguous import
#     and advises `pa.T`, which cannot be written for one's own
#     parameter. The binder settles the name at rung 1. On a `type`
#     declaration the binder does win, so the defect is specific to `fn`
#     signatures — type_param_vs_contested_import_on_type is the green
#     control for that half.
#
#   type_bare_contested_in_imported_module{,_return}   (neg, neg-native)
#   diag_type_position_owner{,_return}                 (diag)
#     A contested bare type written in an imported module resolves
#     silently; the root file gets the ambiguity error for the same
#     shape. The failure surfaces at the caller as a type mismatch, so
#     the diagnostic names the wrong file.
#
#   type_shadows_builtin_{int,string}   (neg, neg-native)
#     A user type sharing a builtin's spelling is accepted, then honoured
#     inconsistently: the annotation resolves to the user type while the
#     use site collapses to the builtin. Functions refuse the same shape
#     outright (neg_shadow_prelude_fn).
#
#   type_union_member_qualified{,_mixed}   (c, native)
#     `type Both = pa.Cfg | pb.Cfg` does not parse, so a union over two
#     homonymous imported sums is unspellable. Positive fixtures: they
#     must compile. Ruled a defect by the owner; the parser fix is a
#     separate lane.
