# rc-leak-baseline.txt — the pinned RC ledger for examples/perceus.
#
# One `<fixture>:<c>:<native>` line per fixture, where each count is
# `alloc_total - free_total` as reported by the runtime ledger under
# KAI_TRACE_RC=1 on that backend. tools/rc-leak-gate.sh runs every fixture
# and fails on any count that differs from its pinned value, on any fixture
# missing from this file, and on any line whose fixture is gone.
#
# `leaked > 0` is not by itself a defect. A program that still holds its
# structure when main returns exits without a final free walk, so whatever
# is live at exit counts as leaked; a fixture that deliberately keeps a
# 200k-node spine alive therefore reports ~200k. What this file protects is
# the exact number: a regression retaining one extra reference per
# iteration moves it, whatever the baseline was.
#
# To read a non-zero count, compare it against the same run's `live_peak`:
# at or below the peak it is the structure the program still holds; well
# above the peak means memory accumulated and was dropped on the floor,
# which is the defect signature.
#
# The two columns differ on a third of the corpus — the backends do not
# agree on how many cells survive to exit — so the count is pinned per
# backend rather than shared. A count that moves on one backend alone is
# as much a regression as one that moves on both.
#
# A new fixture records its measured counts here. When a fix lowers a
# count, the closing lane lowers the line — the ratchet only tightens.
# `-` in a column means the fixture is skipped on that backend; the reason
# lives in tools/rc-leak-skips.txt.
