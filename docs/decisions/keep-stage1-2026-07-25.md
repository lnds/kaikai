# Keep stage1: retirement rejected, capture made loud instead

**Date:** 2026-07-25
**Status:** accepted

## The question

stage1 is 6,945 lines of kaikai-minimal that compiles stage2 (126,645 lines
across 139 modules). Its limitations force documented workarounds across 36
stage2 files, and one class of them costs real debugging time: a lane spent
40+ minutes bisecting a `non-exhaustive match` panic that turned out to be a
stage1 artefact.

Should stage1 be retired from the bootstrap chain?

**No.** The premise that motivated the question was wrong, and the cheapest
fix is unrelated to retirement.

## The premise was wrong

The workaround cluster was believed to be a codegen defect — stage1 "emptying
the second slot of a multi-field variant on destructure". Controlled probes
refute that:

- a slot-2 list in a non-recursive type reads correctly
- a self-recursive list reads correctly
- a structurally identical type with different constructor names reads correctly
- **the same function with the binder renamed from `args` to `xs` reads correctly**

The emitted C shows kaic1 binding the slot correctly and then calling the
prelude `args` builtin. The defect is **name capture**: a pattern binder whose
name collides with one of the 37 entries in stage0's PRELUDE table
(`stage0/emit.c:445`) is shadowed by the builtin, and the read comes back
empty.

`stage2/compiler/law_checks.kai:141-144` already recorded this — as a comment
on one call site, not as a check. The knowledge existed; nothing enforced it.

The symptoms actively mislead: the panic reproduces only on the emit-C path
(not with `-o`), and inserting an `eprint` moves the crash — the signature of
memory corruption, which is why investigation went toward slots and RC rather
than name resolution.

## Options considered

### 1. Checked-in pre-generated `stage2.c` seed — rejected

Commit the 18 MB / 175k-line generated C; a fresh machine runs `cc` on it and
kaic2 rebuilds itself. stage1 is deleted.

Killed by churn: 900 touches to `stage2/compiler` + `main.kai` + `runtime.h`
across 23 of ~25 working days in July 2026 (`runtime.h` alone 68 times). The
seed would be regenerated almost daily.

It also inverts the trust story — a 175k-line generated blob replaces a ~26k-LOC
auditable root and becomes the trust root by fiat — and lengthens the generation
chain onto the known second-generation Perceus surface (#1295).

On the bootstrap promise: the letter of "bootstrap from any machine with cc"
survives, the substance does not. `cc` would compile pre-generated output rather
than derive it from readable source.

### 2. Downloaded N-1 release binary as seed (rustc model) — rejected

Empirically dead: v0.104.0's kaic2 **cannot parse HEAD's stdlib** — it fails on
`pub perm` (`stdlib/effects.kai:92`). Release matrix has exactly one entry
(darwin-arm64), so no Linux seed exists and CI could not bootstrap. And it
requires network, killing offline and air-gapped builds.

This turns "bootstrap from any machine with cc" into "cc + network +
darwin-arm64".

### 3. Freeze stage1 as-is — rejected

Factually not what happens: 74 commits to `stage1/compiler.kai`, 10 in July 2026,
the most recent a feature commit. Formalising the freeze would also cast the
name-capture defect into permanent law, so every future module keeps paying the
workaround tax and the 40-minute failure mode recurs indefinitely.

This is the option the project drifts into by default, because it is the only one
that preserves the bootstrap promise perfectly.

### 4. Make the capture unrepresentable — accepted

Retire nothing. Add a compile-time rejection of pattern binders that collide with
prelude names, so the silent failure becomes a loud error (#1501). The trigger set
is finite and known. Optionally and separately, fix stage1's resolver so local
binders shadow the prelude.

The bootstrap chain is untouched: `cc` → kaic0 → kaic1 → kaic2.

## What this does not solve

Honest accounting of what survives the decision:

- The stage1 maintenance tax remains: the 75-entry `native_handle_fns` allowlist
  (`stage1/compiler.kai:5377`) and the two-copy `runtime.h` sync.
- Generic bundle functions stay impossible: `DFn` in stage1 has no tparams slot,
  so monomorphic duplication remains the workaround.
- Type-driven optimisation stays capped where it depends on information stage1
  does not have. Porting a typer into stage1 was explored and rejected
  repeatedly; the cascade into kaikai-minimal is unbounded
  (`bootstrap-relax-byte-identical-2026-05-22.md`).

The trade accepted here: retirement pays a permanent architectural cost to route
around a defect that is cheaper to prevent than to tolerate, and would leave the
other constraint classes untouched anyway.

## Verification note

`selfhost` byte-id does **not** catch a name-capture regression — the program
still compiles and still emits deterministically. The oracles are runtime
behaviour and the parity corpus.
